### Worktree and log permission requirements

A corrected disposable Git permission fixture was run in a temporary location and removed. The initial targeted run passed 8/8. A broader direct-write fixture passed 12/12, then follow-up testing exposed that metadata made non-writable to Engineer was also unreadable for Git status after a PL commit. The corrected model makes Git administrative metadata PL-owned and read-only to the WO group, and normalizes it after PL Git operations. The final production-equivalent run passed 11/11 with source-writing umask `0007` and Git-operation umask `0027`: Engineer atomic source replacement; denial of top-level worktree entry creation and `.git` pointer rename; denial of canonical source and Git metadata writes; PL staging/commit/push; no group-write mode on normalized Git metadata; and Engineer read-only Git status using exact-path command-scoped `safe.directory` and `GIT_OPTIONAL_LOCKS=0`. The fixture used the existing PL/Engineer UIDs and Engineer's primary group as a temporary WO-group surrogate, without changing account/group databases. Initial harness attempts exposed setup errors (foreign-owner Git safety, bare-repository default branch, and a missing synthetic commit identity); these were corrected and are not evidence of a production boundary failure. No live worktree was created.

For the real worktree, the PL first creates a WO-specific group and assigns only PL and Engineer. Keep the worktree parent PL-owned and non-listable by Engineer (`0711`). The worktree root is PL-owned and not group-writable (`1755` in the fixture), so Engineer cannot add or remove top-level entries, including replacing the `.git` pointer; PL creates any required top-level entries. Keep the Git administrative directory PL-owned and Engineer-non-writable, but readable by the WO group so Git read commands can inspect it. Following each PL Git operation, normalize the `.git` tree to the WO group, directories `2750`, and regular files `0640` (preserve necessary owner execute bits; inspect symlinks and special files); verify no group-write permission, no live lock files, and no credential-bearing content before Engineer access. Place editable source under approved subdirectories with the WO group, setgid, and group read/write (`2770` directories and `0660` files after normalization), so source editors can create and atomically replace files there. Use a source-writing umask such as `0007` and a distinct restrictive Git-operation umask such as `0027`, then normalize and verify modes after every Git operation before Engineer access. One umask does not satisfy both source collaboration and metadata protection. Engineer Git read commands use exact-path, command-scoped `safe.directory` and `GIT_OPTIONAL_LOCKS=0`; never use wildcard or persistent/global trust. This exact permission workflow passed the disposable fixture, but must be retested under the actual WO group before Engineer access. The fixture established filesystem boundaries, not protection against PL executing malicious repository configuration, filters, hooks or agent-controlled Git commands. Assess executable behavior before use; keep Git commands and configuration under PL control.

Role logs must not dirty the canonical checkout or write into the engine installation. Before dispatch, create the permitted WO log directory in the authorized worktree or a separately approved evidence location and verify its owner and mode. Protect `PL.log` against Engineer write, rename and deletion (for example, a PL-owned file in a PL-owned sticky directory); provide a separate Engineer-writable `ENGINEER.log`. Reviewers submit reports to the PL, who records them without granting reviewers Git or filesystem write access. Verify these permissions as each UID. Public logs contain sanitized evidence only; restricted operational evidence remains outside the repository.
